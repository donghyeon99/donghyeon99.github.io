# Portfolio Content Restructure Design

## 목적

김동현의 CV와 프로젝트 6개를 채용 담당자가 빠르게 훑을 수 있으면서, 면접에서는 기술 깊이를 확인할 수 있는 구조로 재정비한다. 현재 사이트의 사실·수치·이미지·이중언어 구조는 유지하고, 정보 계층과 문장 리듬을 개선해 AI가 만든 템플릿 같은 인상을 줄인다.

## 검토 자료

- 현재 Jekyll 사이트의 CV 데이터, 렌더러, SCSS, 프로젝트 6개
- 2026 최신 발표 포트폴리오와 이력서 HTML
- 2024 종합 포트폴리오
- 캡스톤 디자인 원자료
- 이전 개편 결정 메모와 Opus 에이전트 7개의 편집 결과
- 기존 사이트에 반영된 실험 수치, 이미지, 논문, 수상 자료

## 확정된 방향

### 정보 노출

- CV: 핵심 결과와 기여는 기본 노출, 기술 세부사항은 접힘 영역에 배치
- 프로젝트: 면접용 설명 자료이므로 주요 기술 내용과 판단 근거를 기본 노출
- 긴 증빙 자료, 상장, 언론 보도는 후순위 영역으로 분리

### 제목 원칙

- `왜 이 방법을 선택했는가`, `Engineering Decisions`, `시행착오`처럼 평가 의도를 직접 설명하는 메타 제목은 사용하지 않음
- 프로젝트의 기술 대상을 제목으로 사용하고, 선택 이유와 제약은 본문에 자연스럽게 포함
- 공통 정보 순서는 유지하되 실제 제목은 프로젝트별로 다르게 구성

### 문체 원칙

- 국문은 사용자가 선호한 명사형 종결 유지
- `작업. 변수. 구조. 과제.`처럼 지나치게 짧고 기계적인 체언 나열은 자연스러운 명사구로 재작성
- 모든 프로젝트에 동일한 문장 공식을 반복하지 않음
- 판단·제약·검증 과정은 구체적인 상황과 데이터로 표현
- 영문은 완전 문장과 동사 시작 불릿을 혼합하고 연속적인 `-ing` 분사구와 홍보성 표현을 피함

## CV 구조

Work Experience와 Research Experience 모두 다음 정보 계층을 공유한다.

1. 조직·역할·기간
2. 프로젝트명·기간
3. 결과 또는 담당 범위를 요약한 한 줄
4. 핵심 기여 3~4개
5. 접힘 영역
   - 시스템 구성
   - 분석·알고리즘
   - 검증
6. 핵심 기술 5~7개

`tech`와 `keywords`를 한 줄에 무제한 출력하지 않는다. 핵심 기술은 바로 노출하고 검색용 키워드는 축소하거나 보조 영역으로 이동한다. 한국어 화면의 접힘 제목은 `상세 기술`, 영어 화면은 `Technical details`로 표시한다.

## 프로젝트 공통 정보 계층

1. 상단 요약: 역할, 기간, 플랫폼, 가장 강한 결과
2. 프로젝트 배경 또는 문제
3. 역할과 담당 범위
4. 프로젝트별 기술 섹션
5. 실험·검증·결과
6. 관련 자료: 논문, 코드, 영상, 수상, 언론

공통 템플릿 이름은 실제 화면에 노출하지 않는다.

## 시각 구조

- 현재 Chirpy 테마와 색상 체계 유지
- CV의 세부정보는 단순 불릿 대신 2~3열 정의형 레이아웃 사용
- 프로젝트 상단에 작은 Snapshot 블록을 두되 `Snapshot`이라는 단어는 표시하지 않음
- 수치가 있는 프로젝트는 Metric 카드 사용
- ROBIT은 대회별 타임라인 사용
- 이미지가 없는 산업 프로젝트에 빈 플레이스홀더를 만들지 않음

## 사실·공개 범위 제약

- 문서에 없는 사실과 수치 생성 금지
- 골프카트 기간은 2025.06~2026.02 유지
- ROBIT 시작은 2019.01 유지
- GPA 비공개
- 회사 프로젝트의 비공개 수치 추정 금지
- AI 생성 골프카트 이미지는 사용하지 않음
- 전문연구요원은 역할 줄에서만 간단히 표기

## 검증 기준

- KOR/ENG 정보 대응 유지
- CV 세 프로젝트와 Research Experience의 정보 계층 일치
- 프로젝트별 기술 제목은 고유하지만 읽는 순서는 일관됨
- 핵심 수치와 고유명사 변경 없음
- 모바일에서 기간·역할·본문이 겹치지 않음
- 접힘 기능은 키보드와 스크린리더로 접근 가능
- Jekyll 빌드 성공
